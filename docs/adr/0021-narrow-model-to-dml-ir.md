# Narrow model.ts to the DML IR (delete the dead SELECT/GROUP IR)

ADR 0001 named "narrow `model.ts` to the DML IR" as the two-IR endgame, and ADR 0020 declared it done in prose ("`model.ts` narrows to the **DML IR** alone"). The types were never actually removed. `src/ir/model.ts` still defined the full interpreter-era statement IR — `SelectIR`, `SelectFreeIR`, `SelectExprIR`, `GroupIR` — plus their exclusive supporting web (`SelectBaseIR`, the select-shape types, `FilterExprIR`, `ScalarExprIR`, `OrderByIR`, `PageIR`, the `LiteralIR`/`FieldRefIR`/`FunctionCallIR`/… expression atoms, `BacklinkSourceIR`/`LinkRelationIR`, `ScopeTreeIR`, `SchemaTypeRefIR`, `TriggerIR`/`PolicyIR`, and the `Depth` recursion helpers). So `CONTEXT.md` called `model.ts` the "narrowed remainder" of a narrowing that hadn't happened — exactly the kind of doc/code drift a future reader trips over.

**The gap (measured).** A repo-wide scan of every symbol imported `from "…/ir/model"` returned only eight names: the DML types (`InsertIR`, `InsertLinkPropertyIR`, `InsertLinkDefaultIR`, `UpdateIR`, `UpdateLinkAssignmentIR`), `IRStatement`, `OverlayIR`, and `SelectIR`. No wildcard or barrel re-export exists. `SelectFreeIR` / `SelectExprIR` / `GroupIR` had **zero references** anywhere outside `model.ts`; `SelectIR` survived only through one stale `compiled.ir as SelectIR` cast in `engine.ts` — and per ADR 0001 `compiled.ir` is the DML IR or `undefined` for a SELECT, so that cast actively lied about the value's type. The engine also fabricated seven write-only `{ kind: "select"/ast.kind, rows: [] } as unknown as IRStatement` placeholders in `QueryExecutionTrace` records, whose own doc comment already said the field is "undefined for SELECT / GROUP". `runGroupIR` (the function) was already gone in ADR 0020's group-SQL work; only stale comments referenced it.

**Decision (done):**

- **Delete the dead statement IR and its exclusive supporting web** from `model.ts` (~600 lines). What remains is exactly the DML IR and the types it structurally needs: `PathStepIR`/`PathIdIR`, `OverlayIR`, `Cardinality`/`Multiplicity`/`Volatility`/`InferenceResult`, the statement bases (`PathStatementIR` / `TableStatementIR` / `MutationBaseIR`), the `Insert*` / `Update*` / `Delete*` types, and `IRStatement = InsertIR | UpdateIR | DeleteIR`.
- **Fix the lying cast**: `const ir = compiled.ir as SelectIR` → `const ir = compiled.ir` (type `IRStatement | undefined`); drop the now-unused `SelectIR` import.
- **Remove the seven synthetic select placeholders**: `ir: { kind: "select", … } as unknown as IRStatement` → `ir: undefined` (the trace field is `IRStatement | undefined`, and the placeholders were verified write-only — nothing reads `traces[].ir.kind`/`.rows`; the only `c.ir` reads on the write path are on freshly-compiled DML IRs, e.g. `runWriteWithAccessPolicies`).
- **Simplify the two now-redundant branches**: `extractOverlays` collapses from a four-kind switch to `ir ? ir.overlays : []` (all DML IRs carry `overlays`); the INSERT-path `if (ir && ir.kind !== "select" && …)` guard collapses to `if (ir)` (the `!== "select…"` arms are now provably true).
- **Reword the stale comments** in `service.ts` (a `select_expr` wrapping a group degrades to a fallback artifact handled by the engine's runtime grouper `preEvaluateGroupBindings` — not a "legacy `compileToIR` / `GroupIR`" path that no longer exists), and replace the `CONTEXT.md` "Routing shim" entry with a "Statement routing (no shim)" note.

**Why this is safe.** `npx tsc` is the proof the deletion is complete and correct: narrowing `IRStatement` makes any DML type that still needed a deleted supporting type a hard error. Exactly one surfaced — the INSERT-path `ir.kind !== "select"` comparison ("no overlap") — and it was a tautology to simplify, not a real dependency. The runtime edits are behaviour-equivalent by construction (write-only placeholders → `undefined`; `extractOverlays`/guard reduce to their DML-only form).

**Verification.** Behaviour-neutral: the most-affected slice (`insert` / `delete` / `for` / `group` / `select`, 962 tests — the DML write path, FOR-over-SELECT where the `as SelectIR` cast lived, and the group fallback) ran `179 failed / 780 passed / 3 skipped` **identically** before and after (the failures are the pre-existing partial-conformance baseline). The compile-pipeline + inference + DML goldens (`inspect` / `inspect_corpus` / the five `edgeql_ir_*` / `edgeql_ir_pathid` / `sql_dml`) stay green (291 pass / 141 documented skips). 0 type errors. −~600 lines.

**Consequences.** `model.ts` is now literally the DML IR and nothing else; `CONTEXT.md`'s "narrowed remainder" claim is true rather than aspirational. The engine routes on the AST's `statement.kind` with no synthetic-IR residue, and `CompileArtifact.ir` is honestly DML-or-`undefined`. The two-IR era leaves no dead types behind.

**Why record it:** a future reader comparing ADR 0020 (which said the narrowing was done) against a `model.ts` that still held SELECT/GROUP IR would be confused about which is authoritative. This records that 0020 completed the *oracle deletion* and *inference parity*, while the *model.ts narrowing* it described in prose was finished here — the dead SELECT/GROUP IR was genuinely unreferenced, and the write-only trace placeholders were the last residue of the routing shim.
