# Wire scope-tree validation into the Live IR (the last inference dimension)

The final dimension of candidate 6 (Live-IR inference parity → retire the `semantic.ts` oracle, ADR 0001). Unlike volatility/cardinality/multiplicity/type — which are *values* the oracle computes and the Live IR can additively reproduce — **scope-tree** is **error-detection**: its 6 cases assert that the compile *throws* a correlated-reference violation (a path that "changes the interpretation of 'X' elsewhere in the query", or a correlated set referenced inside a nested mutation). So it is not additive: making the Live IR throw could over-reject queries it currently compiles.

**The gap (measured).** `checkScopeTreeViolations(statement, schema)` already exists as a standalone module (`src/compiler/scope_tree_check.ts`), called by the oracle's `compileToIR` (semantic.ts:508) but **not** by `compileASTToGelIR`. A probe confirmed the Live IR compiled all 5 throwing scope cases without diagnosing them.

**Decision (done):** Call `checkScopeTreeViolations(statement, ctx.schema)` in `compileASTToGelIR`, right after parameter validation and before lowering. Reusing the oracle's existing check (not a re-implementation) — one home for the rule. It is deliberately **NOT** guarded by the additive `try/catch` the value-inferences use: throwing the violation is the entire point. All 6 cases now match the oracle (`tests/edgeql_ir_scopetree_live.test.ts`): bad_01/04 → "reference to 'User.name' changes the interpretation", bad_02/03 → "reference to 'User' …", bad_06 → "cannot reference correlated set 'User' here", bad_05 → compiles (the lenient case).

**Why this is safe (no over-rejection — verified, since it is NOT additive).** A stash-based before/after on a 12-suite behavioural slice (`select` / `insert` / `delete` / `for` / `group` / `expressions` / `functions` / `coalesce` / `advtypes` / `linkprops` / `scope` / `filter`, 2043 tests) went `749 failed / 1291 passed` → `748 / 1292` — **one fewer failure, zero new**: no production query that previously compiled now throws, and one test that expected the rejection now passes. The check is conservative enough to add to the production path without regressions. 0 type errors; all four other live dimensions and the oracle's scope-tree test stay green.

**Consequences.** All five inference dimensions (volatility, cardinality, multiplicity, type, scope-tree) now reach parity on the Live IR. The Live IR no longer silently accepts the correlated-reference violations the oracle rejects. With every dimension reproduced, the path is clear to delete `semantic.ts` (and repoint/replace its 5 oracle tests with the `*_live` counterparts) — the ADR-0001 endgame — modulo the handful of intrinsically out-of-scope cases (shape-element cardinality/type = SQL-builder concern; the 2 multiplicity error-detection cases).

**Why record it:** a future reader will see `checkScopeTreeViolations` called from BOTH `compileASTToGelIR` (Live IR) and `compileToIR` (oracle). That is intentional during the transition — it is one shared check, not a duplicate; when the oracle is deleted, only the Live-IR call remains. The check runs un-guarded on every production compile by design (it is a validation), and was verified not to over-reject.
