# AST-driven CREATE TYPE registration (Stage D1c, part 1)

D1b made `parseDDL` carry the parsed `CREATE TYPE` body on the AST (`DDLStatement.createTypeBody`). This step repoints the runtime's type registration onto the AST, removing the `CREATE TYPE` half of the string shadow-parser.

**Decision (done):** `registerDynamicTypeDDL` (`runtime/engine.ts`) no longer string-parses the statement. It parses to the AST via `parseEdgeQL` (guarded by `tryResult` — a non-parseable or non-`CREATE TYPE` statement simply returns false, matching the old `parseCreateTypeHeader` returning `null`), then reads the header straight off the `DDLStatement`: `name`, `extendsList`, and `abstract` (from `modifiers`). The body loop iterates `ast.createTypeBody ?? []` instead of calling `parseCreateTypeBody(bodyText)`. The conversion to `TypeDef` (scalar resolution, FK synthesis, inheritance merging, `schema.addType`) is unchanged — only the *source* of the structured members and header changed, from a bespoke string parse to the EdgeQL parser's own output.

**Deleted (now orphaned):** `parseCreateTypeHeader` and its `ParsedCreateTypeHeader` interface (`runtime/ddl.ts`), the now-dead brace-helper re-export there (its only consumer, `engine.ts`, no longer imports it — the brace helpers live in `edgeql/ddl_body.ts` and are used internally by `parseCreateTypeBody`), and the `parseCreateTypeBody` / `parseCreateTypeHeader` / `extractTrailingBraceBlock` / `stripTrailingBraceBlock` imports in `engine.ts`. `CREATE TYPE` no longer has any string-level shadow parse — the parser parses it once onto the AST and the runtime reads it.

**Verification.** `npx tsc` 0 errors. Behaviour-neutral (or better): `edgeql_userddl` / `inspect` ran `2 failed` identically before and after; the DDL-heavy `edgeql_insert` / `linkprops` / `linkatoms` slice went `112 failed → 111 failed` (one *fewer* failure, **zero new** — the AST parse handles a case the old string header parser didn't, within the suite's flakiness band; not a regression). `tests/ddl_ast_body.test.ts` + `tests/ddl_body.test.ts` stay green.

**Decision (still pending — D1c parts 2/3):** `ALTER TYPE` (`parseAlterTypeStatement` → `applyAlterTypeDDL`) and `CREATE FUTURE` flags (`parseCreateFutureFlag`) are still string-parsed in the pre-pass. Porting `ALTER TYPE` ops onto the AST (`alterTypeOps`) and routing those + future flags through the AST is the remaining work to delete the shadow parser entirely and make the whole pre-pass parse the script once.

**Why record it:** a future reader will see `registerDynamicTypeDDL` call `parseEdgeQL` and read `createTypeBody` — that is the parser-owns-the-body design (D1b/0029) being consumed here. `parseCreateTypeHeader` is gone, not relocated; the `ALTER TYPE` string parser remaining is deliberate, the next step, not an oversight.
