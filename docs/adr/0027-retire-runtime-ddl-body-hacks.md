# Retire the runtime's `CREATE TYPE` body hacks (Stage C of the front-end unification)

Stage B (ADR 0026) added `parseCreateTypeBody` — the structured, unit-tested parser for a `CREATE TYPE` body — additively. This ADR is **Stage C**: route the runtime through it and delete the hand-rolled token-walker + regex helpers that re-parsed those bodies on the live write path. This is the concrete payoff of the unification effort (the `unified-bubbling-moon` plan): the fragile schema-parsing-by-regex is gone, replaced by one parser with a test surface.

**Decision (done):** `registerDynamicTypeDDL` (`runtime/engine.ts`) now calls `parseCreateTypeBody(bodyText)` once and converts the structured entries (`property` / `link` / `computed_link` / `alter_pointer` / `type_exclusive_constraint`) to the runtime's `TypeDef` shape. The **conversion** — scalar resolution (`dynamicScalarFromType`), inline-FK synthesis, type-constraint field-ref extraction (`exclusiveConstraintFieldRefs`), default lowering (`literalDefaultFromText`), and crucially the live-schema **inheritance merging** and the `schema.addType` call — is **preserved verbatim**; only the parsing source changed. A small `exclusiveConstraintDefs(specs)` helper maps the parser's `ExclusiveConstraintSpec[]` to the `ConstraintDef[]` the exclusivity machinery consumes (replacing `collectDynamicExclusiveConstraints`).

**Deleted (≈209 lines, grep-confirmed orphaned after the rewrite):** `parseMemberHeader`, `parseAlterPointerHeader`, `parseExclusiveConstraintEntry`, `collectDynamicExclusiveConstraints`, `extractInlineDefaultText`, `sliceTokenRange`, the `MEMBER_MODIFIER_KINDS` set, and the `MemberHeader` type. `stripBacktickName`, `splitTopLevelScriptStatements`, and the conversion helpers stayed (still used elsewhere).

**One reconciliation.** The `DynamicExclusiveConstraint` type (deleted with the parsers) turned out to be shared by a *separate*, self-contained ALTER-statement constraint parser (`drop_constraint` / `create_constraint` handling) whose shape is identical to the new `ExclusiveConstraintSpec`. Those three references were repointed at `ExclusiveConstraintSpec` (imported), deduping rather than re-adding the type. (That ALTER parser is a *second* inline exclusive-constraint parser — out of scope here, a candidate for a future consolidation.)

**Parity, including a preserved latent gap.** The conversion is byte-equivalent to the old per-entry logic, so behaviour is unchanged — including the `DELEGATED` gap ADR 0026 documents (the tokenizer emits `kw_unreserved`, so a `CREATE DELEGATED CONSTRAINT exclusive` was, and still is, dropped). Closing it stays a separate behaviour-changing fix.

**Verification.** `npx tsc` 0 errors. Behaviour-neutral: the DDL slice (`edgeql_userddl` / `edgeql_insert` / `inspect` / `inspect_corpus` / `linkprops` / `linkatoms` + the `ddl_body` unit tests) ran `114 failed / 369 passed` **identically** before and after (the failures are the pre-existing partial-conformance baseline; the structured `ddl_body` tests are green). The deleted helpers had no callers outside the rewritten loop (verified by reference count before deletion and by the clean type-check after).

**Consequences.** The runtime no longer re-parses `CREATE TYPE` bodies by hand — schema declaration parsing has one structured home (`ddl_body.ts`) with a unit-test surface, and the live write path is fed structured members instead of regex-scraped strings. Stage D (fold `parseCreateTypeBody` into `parser.ts::parseDDL` so the AST carries the body, then unify the tokenizers) remains gated — this stage banked the value independently.

**Why record it:** a future reader will see `registerDynamicTypeDDL` consume `parseCreateTypeBody` and may wonder where the old token-walker went. It was deleted here, deliberately — the structured parser (ADR 0026) replaced it with no behaviour change. The ALTER-path constraint parser sharing `ExclusiveConstraintSpec` is the remaining inline constraint parser; it is intentionally untouched (a separate consolidation), not missed.
