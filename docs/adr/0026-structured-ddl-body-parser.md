# A structured parser for `CREATE TYPE` bodies (Stage B of the front-end unification)

The feasibility spike for unifying the two language front ends (EdgeQL+DDL vs SDL — see the round-4 review and the `unified-bubbling-moon` plan) found that the EdgeQL DDL parser `skipDDLBody()`s every `CREATE TYPE { … }` body, and the **runtime re-parses those bodies by hand** in `registerDynamicTypeDDL` (`engine.ts`) via a token-walker (`parseMemberHeader`) plus regex/token helpers (`parseExclusiveConstraintEntry`, `collectDynamicExclusiveConstraints`, `extractInlineDefaultText`, `parseAlterPointerHeader`). That hand-rolled schema parsing on the live write path is the genuinely fragile wart the unification targets, and it had no test surface but executed rows. This ADR is **Stage B**: give that body grammar one structured home with a real unit-test surface, additively, before the runtime is switched over (Stage C, ADR 0027) and ahead of any grammar/tokenizer merge (Stage D, gated).

**Decision (done):** add `src/runtime/ddl_body.ts` exporting `parseCreateTypeBody(bodyText): CreateTypeBodyEntry[]` — the single structured parser for a `CREATE TYPE` body. It turns the body text into a discriminated list of entries — `property` (name / target / required / multi / inline exclusive constraints / default text), `link` (+ link-properties), `computed_link` (`:= <expr>`), `alter_pointer` (an `ALTER PROPERTY|LINK … { CREATE CONSTRAINT exclusive }`), and `type_exclusive_constraint` (a type-level `CREATE CONSTRAINT exclusive [ON …] [EXCEPT …]`). It reuses the EdgeQL tokenizer (as the old token-walker did) and the brace helpers in `ddl.ts`; it is **parse-only** (no scalar resolution, no FK synthesis, no schema mutation), so it is pure and unit-testable.

It is purely **additive** — nothing imports it yet; `registerDynamicTypeDDL` is untouched (that is Stage C). `tests/ddl_body.test.ts` (24 tests) pins every member shape — modifiers, `->`/`:`/`:=` separators, collection target types, inline + type-level exclusive constraints, `ON`/`EXCEPT`, link-properties, `SET default :=` / bare `default :=`, the `std::` qualifier, multi-member bodies, and the drop of non-exclusive constraints.

**Parity is the design constraint, including a preserved latent gap.** The port reproduces the prior token-walker's behaviour exactly, so Stage C can flip over with no behaviour change. The one notable case: the EdgeQL tokenizer emits `DELEGATED` as `kw_unreserved`, not `identifier`, so the old code's `kind === "identifier" && lower === "delegated"` check **never matched** — meaning a `CREATE DELEGATED CONSTRAINT exclusive` was dropped entirely (the parse bailed before reaching `kw_constraint`). `parseCreateTypeBody` keeps that exact behaviour (verified by tests asserting the dropped result). Closing the gap (accept `kw_unreserved` for `delegated`) is deliberately **out of scope** — it would be behaviour-changing, because exclusive constraints that are silently ignored today would start being enforced, shifting query results. It is now visible and testable in one place, a candidate for a separate behaviour-gated fix.

**Decision (deferred to Stage C / D):** the conversion of these structured entries to `TypeDef` — scalar resolution (`dynamicScalarFromType`), inline-FK synthesis, type-constraint field-ref extraction, and the live-schema **inheritance merging** — stays in `registerDynamicTypeDDL` and is rewired to consume the structured entries in Stage C (ADR 0027). Folding the parser into `parser.ts::parseDDL` (so the AST carries the body) and unifying the tokenizers is Stage D, gated on Stage C's value.

**Verification.** `npx tsc` 0 errors; `tests/ddl_body.test.ts` 24/24 green; the module is imported by nothing (grep-confirmed additive), so the production path and the full suite are unchanged by definition.

**Why record it:** a future reader will see schema-body parsing in two places — `ddl_body.ts` and the runtime's `parseMemberHeader`/regex helpers — during the Stage B→C window. That is intentional and temporary: Stage B builds and tests the structured parser additively; Stage C routes the runtime through it and deletes the hand-rolled helpers. The `delegated` drop is a faithfully-preserved latent gap, not a new bug — do not "fix" it inside this neutral refactor.
