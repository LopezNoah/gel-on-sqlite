# Live-IR volatility inference (first step toward retiring the oracle)

The round-3 review's candidate #6 is the standing ADR-0001 follow-up: reach inference parity on the **Live IR** so the ~9.6k-line interpreter-era oracle (`semantic.ts`) — kept alive only because the 5 `edgeql_ir_*_inference` tests assert against its `volatility`/`cardinality`/`multiplicity`/`scopeTree`/`stype` output — can be deleted. ADR 0001 measured the gap as "11 of 17 volatility cases fail when ported to `compileASTToGelIR`". This ADR closes the **volatility** dimension.

**The gap (re-measured).** A probe ran all 17 volatility cases through `compileASTToGelIR` and read `Statement.volatility`: **6/17 matched**, and only by coincidence — the Live IR hardcoded every statement's volatility to the `defaultVolatility` (`"stable"`) from `statementBase`. It performed no propagation: a `WITH foo := random()`, a `FILTER random() > 0.9`, an `INSERT`, a literal binding — all came back `"stable"`.

**Decision (done):** Add `src/compiler/inference.ts` — the home for Live-IR inference — with `inferStatementVolatility(statement, schema, activeModule)`. The volatility rules are **ported from the oracle's inference closure** (`semantic.ts`): the `immutable < stable < volatile < modifying` lattice, `maxVolatility`, function-volatility resolution (`tryResolveStdlibFunction` then `schema.findFunction`), and the mutually-recursive walks over the AST (type-name / filter / order-by / WITH-binding / free-expr), with a statement's volatility the max over its source, bindings, FILTER, ORDER BY, LIMIT, OFFSET, and shape computeds; mutations are `modifying`. `compileASTToGelIR` calls it once per compile and writes `Statement.volatility`. Result: **17/17** volatility cases now match the oracle on the Live IR, pinned by `tests/edgeql_ir_volatility_live.test.ts` (the counterpart to the oracle's `edgeql_ir_volatility_inference.test.ts`, which is left untouched and still green).

**Why this is safe (purely additive, and guarded).** Nothing on the execution path reads `Statement.volatility` — the only `.volatility` reads in `engine.ts` are UDF *declaration* volatility, unrelated to this field; `inspect.ts` and the SQL lowering do not read it either. So computing it cannot change any query result; a wrong value could only fail the new test, never execution. The walk's `switch`es are TypeScript-exhaustive and unknown functions resolve to `volatile` (rather than throwing as the oracle does), but it is **not** unconditionally total: a pathological AST — e.g. a self-referential `WITH x := x` — makes the type-name↔binding recursion unbounded and overflow the stack. Because this inference now runs on **every** production compile (unlike the oracle, reachable only from 5 tests), that throw would break a real query. The call is therefore wrapped in a `try/catch` that **keeps the default volatility on any error** — correct precisely because the field is additive decoration, not a correctness input (contrast ADR 0012's probe, whose result drives execution and so must propagate defects). Confirmed empirically: unguarded, the broad 17-suite slice (2229 tests) regressed by one (`761 failed`) — a real throw; with the guard it is `759 failed / 1363 passed` (≤ the `760` pre-existing partial-conformance baseline, within the suite's ±1 order-flakiness) — zero new failures.

**Decision (deferred, with reason):** the oracle is **not** deleted. Volatility is one of five dimensions it pins; **cardinality (183 assertions), multiplicity (106), type (7), and scope-tree** still have no Live-IR equivalent (286 of the 307 inference assertions). `semantic.ts` stays the oracle until those are ported into `inference.ts` too. The duplication (volatility rules now exist in both `inference.ts` and `semantic.ts`) is the same temporary state ADR 0001 describes — it resolves when the oracle is removed, not before.

**Consequences.** Inference has a home (`inference.ts`) that the Live IR populates, and volatility parity is reached and locked by a test. The path to deleting `semantic.ts` is now "port the remaining four dimensions into `inference.ts`, then repoint the 5 oracle tests at the Live IR and delete the oracle" — one dimension at a time, each verifiable the same way.

**Why record it:** a future reader will find volatility inference in **two** places (`inference.ts` and `semantic.ts`) and may delete one as a duplicate. Both are needed until the oracle goes: `inference.ts` feeds the Live IR; `semantic.ts` is still the oracle for the other four dimensions. Delete the oracle only once all five dimensions are ported (ADR 0001).
