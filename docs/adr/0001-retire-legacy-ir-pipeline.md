# Retire the legacy IR routing path (retain semantic.ts as an inference oracle)

The query path historically carried two IRs: the interpreter-era **Legacy IR** (`src/ir/model.ts`, produced by `src/compiler/semantic.ts`) and the **Live IR** (`src/ir/gel_ir.ts`, produced by `src/compiler/ast_to_ir.ts` and lowered to SQL by `src/sql/gel_ir_compiler.ts`). The Live IR became primary for SELECT, GROUP, and DML, leaving `semantic.ts` (~9.6k lines) with no production caller — `service.ts` kept it reachable only by fabricating a synthetic kind-only `IRStatement` (`traceIRFromGelIR`, the *routing shim*) so the engine's `ir.kind` dispatch still compiled, and 5 `edgeql_ir_*_inference` tests asserted against its inference output.

**Decision (done):** Delete the routing shim and route the engine on the AST's `statement.kind` (not `gelIr.kind`, to avoid coupling the engine to the Live IR's internal kind strings; not a new explicit discriminator, to avoid a third source of truth). `CompileArtifact.ir` is now the **DML IR** (`Insert*` / `Update*` / `Delete*`), present only for mutations; SELECT / GROUP / FOR execute off the gelIR SQL artifact. `validateGroupByAtomCollisions` was relocated into `ast_to_ir.ts`, so the live compile pipeline no longer imports `semantic.ts`.

**Decision (deferred, with reason):** `semantic.ts` and the Legacy IR are **retained**, not deleted. The intended plan was to port the 5 inference tests onto the Live IR's own `volatility` / `cardinality` / `multiplicity` / `scopeTree` / `stype` fields and then delete `semantic.ts`. A probe refuted the premise: porting the volatility suite to `compileASTToGelIR` failed **11 of 17** cases — the Live IR carries those fields but does **not** populate them with the fidelity of the `semantic.ts` inference engine. Deleting `semantic.ts` would silently drop 307 passing inference assertions the Live IR cannot yet reproduce. `semantic.ts` is therefore quarantined as an **inference oracle**, reachable only from the 5 `edgeql_ir_*_inference` tests.

**Consequences.** Deleting `semantic.ts` (and narrowing `model.ts` to the DML IR) is unblocked only once the Live IR reaches inference parity — i.e. `ast_to_ir.ts` populates `volatility`/`cardinality`/`multiplicity`/`scopeTree` to match the cases in the 5 inference tests. Until then the two IRs coexist: the Live IR runs production; the Legacy IR exists solely so its inference stays under test. A future architecture review should treat "reach Live-IR inference parity, then delete `semantic.ts`" as the follow-up, not re-litigate the two-IR split.

**Why record it:** a future reader will see one IR where it looks like there should be one, and will be tempted to delete the 9.6k-line `semantic.ts` as dead code. It is not dead — it is the inference oracle, and the Live IR cannot replace it yet. The shim removal was test-gated against two clean runs of the order-flaky vitest suite (0 regressions).
