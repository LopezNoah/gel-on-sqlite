# One home for the link-storage rule (`usesLinkTable`)

The architecture review's round-2 candidate #1 found that the rule "a link is stored in a separate junction table (vs. an inline `<name>_id` column) iff it is `multi` or carries link-properties" was re-derived across the **live** pipeline even though `usesLinkTable` already existed as an exported predicate in `codegen/sql.ts`: the boolean `Boolean(link.multi) || (link.properties?.length ?? 0) > 0` was inlined twice in `runtime/engine.ts`, and `schema/migrations.ts` encoded the same rule (and its negation, `!multi && properties.length === 0`) five times over declarative `member` shapes. A leaky seam: the exported predicate took a `LinkDef`, so callers holding a declarative `LinkMember` re-implemented it instead of importing.

**Decision (done):** Promote `usesLinkTable` to the schema core (`src/schema/schema.ts`, a cycle-safe leaf that already hosts `qualifiedTypeName`) with a **structural** parameter — `{ multi?: boolean; properties?: readonly unknown[] | null }` — so both a `LinkDef` and a declarative `LinkMember` satisfy it without either type importing the other. `codegen/sql.ts` now re-exports it (the public-API barrel in `index.ts` is unchanged); `engine.ts` (2 sites) and `migrations.ts` (5 sites, positive form `usesLinkTable(member)` and negated form `!usesLinkTable(member)`) consume it. The substitution is provably boolean-equivalent — declarative `properties` is always a present array, so `?? 0` and the explicit length checks agree.

**Decision (scoped out, deliberately):** the **inference oracle** (`src/compiler/semantic.ts`) keeps its eight inline copies of the rule. It is quarantined per `docs/adr/0001` — reachable only from the 5 `edgeql_ir_*_inference` tests and slated for **wholesale deletion** once the Live IR reaches inference parity, not for refactor investment. Routing it through the shared predicate would touch a 9.6k-line file destined for removal, for no live-pipeline locality gain.

**Verification.** Behaviour-neutral: the link/codegen/DDL/inspect slice (`codegen_sql` / `linkprops` / `linkatoms` / `userddl` / `inspect`, 156 tests) ran `61 failed / 95 passed` both before and after (the failures are the pre-existing partial-conformance baseline). 0 type errors. A `codegen_sql` unit test that passed full `LinkDef` literals was tightened to the predicate's actual inputs (`{ multi: true }`, `{ properties: [...] }`, `{}`).

**Consequences.** The live pipeline derives link storage from one predicate; the negated `!multi && length === 0` form can no longer drift from the positive form. The remaining oracle copies are documented (here and in the predicate's doc comment) as deliberate, not missed.

**Why record it:** a future reader will see `usesLinkTable` shared across `engine`/`migrations`/`codegen` but eight copies still inline in `semantic.ts`, and may assume the dedup was incomplete. It was intentional — the oracle is quarantined per ADR 0001 and goes away whole.
